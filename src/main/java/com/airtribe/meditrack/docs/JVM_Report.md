### JVM
- The engine that actually runs Java programs by converting Java instructions into commands the computer understands.

- It sits between the program and the operating system

- Different OS → different JVM implementation

### JRE
- The JRE is everything we need to run a Java program.

- It includes - JVM and Core Java libraries (like String, List, Scanner, etc.)


### JDK
- The JDK (Java Development Kit) is a complete set of tools used by developers to write, compile, and run Java programs. It includes the JRE and extra tools like the Java compiler.


### Byte Code

- Bytecode is an intermediate form of code generated by the Java compiler (javac).
  Instead of converting Java code directly into machine-specific instructions, the compiler produces platform-independent bytecode (.class files), which is executed by the JVM.


### WORA (Write Once, Run Anywhere)

- Write Once, Run Anywhere (WORA) means that a Java program needs to be written and compiled only once.
  The same bytecode can then run on any operating system that has a compatible JVM, without requiring any changes to the source code.

- When we write Java code, it is compiled into bytecode, which is a special, platform-independent format. This bytecode is not tied to Windows, macOS, or Linux. The JVM on each operating system knows how to run the same bytecode. This is why Java follows the idea of “write once, run anywhere” - we can write a Java program once, and it will run on any system that has a JVM installed, without changing the code.


### Class Loader

- The Class Loader subsystem loads .class files into memory when they are required by the program.
- `Bootstrap ClassLoader`: Loads core Java libraries like java.lang, java.util
- `Application ClassLoader` : Loads classes from application classpath
- `Extension ClassLoader` : Loads classes from external jar files

### Runtime Data Areas
The JVM divides memory into different areas called Runtime Data Areas.

- `Heap` : The Heap stores objects and instance variables.
  -  Shared among all threads 
  - Managed by Garbage Collector
  - Largest memory area in JVM

- `Stack` :  Each thread has its own Java Stack.
  - Local Variables
  - Method Calls
  - Partial Results
- `Method Area` : Shared among all threads
  - Class metadata
  - Static variables
  - Method bytecode
  - Runtime constant pool
- `Program Counter` : Each thread has its own Program Counter. Stores address of currently executing JVM instruction

### Execution Engine
- Executes the bytecode instruction
- Optimize execution
- Manage memory cleanup

- It consists of 
  - Intepreter
  - JIT Compiler
  - Garbage Collector
